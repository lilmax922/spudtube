# 0008 Typography scale and reusable tokens

SpudTube had no reusable type scale: `hero-carousel.vue:202` hard-coded `38px/800/1.15`, `title-identity-block.vue:87` `30→34px/800/-0.02em`, `content-row.vue:55` `16.5px/700/tight`, `my-list.vue/search.vue/title-not-found.vue` `2xl/700` vs `18px/700`, and `title-card.vue/availability-panel.vue` scattered `13px/11px/12.5px/10px` plus `text-sm`/`text-xs` ad-hoc. The design system (`design-system.md:62-77`) only set principles (`14/400/1.7` anchor, `Outfit 400/500/700/800`, `tabular-nums` limited to metadata) without concrete sizes. We needed a single truth for 12 reusable levels that mirrors the `ADR-0007` gutter approach (`tailwind.css :root` vars, two-step responsive) and keeps `Outfit`'s four weights without adding `600`.

We decided on 12 tokens at `tailwind.css :root/.dark` as the single truth: `--text-display 44/800/1.1/-0.02em/balance` (shared by `hero-carousel` and `title-identity-block`, responsive `32@880→28@560`), `--text-heading-xl 24/700/1.25/-0.015em`, `--text-heading-lg 20/700/1.3/-0.01em`, `--text-heading-sm 16.5/700/1.3/-0.01em`, `--text-heading-xs 13/700/1.4/0.06em` (no `text-transform`; case depends on source text), `--text-body-lg 16/400/1.6`, `--text-body-md 14/400/1.7`, `--text-body-sm-strong 14/500/1.6/0.2px`, `--text-caption-md 13/400/1.4/0.1px`, `--text-caption-sm 12/400/1.5/0.4px` (`11@560`), `--text-button-md 14/500/1.6/0.2px`, `--text-link-md 14/500/1.4/0.3px`, each with `--leading-*`/`--tracking-*`/`--weight-*`. They are consumed via `@layer utilities .text-display` etc and `@layer base { h1→display, h2→heading-xl, h3→heading-sm, h4→heading-xs }`, with `max-width` media only for `display` and `caption-sm`, reusing the `880/560` container breakpoints from `ADR-0007`.

## Considered Options
- Fixed `px` per breakpoint vs fluid `clamp()` for `display` — picked fixed two-step `44→32→28` to stay aligned with the `24→40@880` gutter model and keep validation predictable; `clamp()` deferred until a marketing `display-xl 64` is needed.
- CSS vars at `:root/.dark` vs `@theme inline` vs `theme.extend.fontSize` — picked `:root` arbitrary `var()` (as in `0007`) to keep `tailwind.css` as the single truth without extra indirection.
- Heading weight ladder `500` vs `700/800` — kept `display 800` / headings `700` / bodies `400` / strong/button `500` to stay within the frozen `400/500/700/800` Google Fonts load and let `size/leading/tracking` carry the hierarchy, not a new `600`.
- Letter-spacing/`font-feature` (`0.2px/0.4px` + `"calt","ss03"`) vs SpudTube's `tight/-0.02em/0.06em` — kept SpudTube's `tight/-0.02em/0.06em` and relied on `Outfit`'s built-in `calt/kern/liga`, dropping `ss03` which is `Inter`-specific.
- Token naming `h1~h4` vs semantic `display/heading-xl…` — picked semantic `display/heading-*` with `h1~h4` as a thin base mapping, avoiding tag-vs-visual coupling.
- Full app vs first-batch migration — migrated whole app in this batch (all `text-[13px]/text-sm/text-xs` etc to `text-*` utilities, plus scoped `font-size: 10px/12.5px/13px/14px/19px` in `app.vue/filter-bar.vue/title-card.vue` to `var(--text-*)`) to avoid a second `vitest` snapshot churn; the alternative of four-file first-batch was rejected because the token surface is small and the build regression is the same.

## Consequences
- `design-system.md` `Typography` becomes a contract table referencing `{text.display}` etc, with `tailwind.css` as the source and `docs/design/prototype.html` remaining non-authoritative.
- `hero-carousel.vue` `.heroTitle`/`.heroSub`/`.heroMetaLine` and `title-identity-block.vue` `h1` now read `var(--text-display)` etc; `content-row.vue` `h3` reads `heading-sm`, `my-list.vue/search.vue/title-not-found.vue` read `heading-xl`, section labels read `heading-xs`, bodies read `body-md`, captions read `caption-md/sm`, chips/buttons read `button-md`.
- App shell (`app.vue .logo` `19→heading-lg`, `kindSwitchBtn`/`#appnav a` `13/14→caption-md/button-md`, responsive `17→heading-sm`/`13→caption-md`) and `filter-bar`/`title-card` scoped styles now consume `var(--text-*)`.
- No new `CONTEXT.md` terms (typography is not domain vocabulary); verification is `pnpm lint --fix && typecheck && build` plus `vitest` snapshot updates limited to typography assertions (`text-display`/`text-heading-xs`/`text-body-md`), and visual diff at `560/880/1280/1680/1920` for `display 44→32→28` and `caption-sm 12→11`.
- Inter/weight `600` and `font-feature ss03` are explicitly not adopted; `tabular-nums` stays scoped to numeric rows (`title-identity-block` meta row) rather than tokenized.
